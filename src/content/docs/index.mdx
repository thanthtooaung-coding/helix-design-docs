## What this is

A master technical design document, written to be implemented. Every major decision follows the same
structure: **problem → candidate solutions → comparison → decision → why → tradeoffs → operational
implications**. Where a decision is genuinely open, it is marked as such rather than resolved by fiat.

Every component carries a maturity label, because the biggest failure mode for a project of this scope
is building the <span class="mat mat-scale">SCALE</span> version of everything on day one:

- <span class="mat mat-mvp">MVP</span> — needed to get `git push` → live URL working on one machine.
- <span class="mat mat-v1">V1</span> — needed before untrusted third-party code runs on shared infrastructure.
- <span class="mat mat-scale">SCALE</span> — needed beyond roughly 10k tenants or multiple regions.

## The core decision

Everything a customer can deploy — a Spring Boot fat jar, a Go binary, a PHP app, a hand-written
Dockerfile — becomes an **OCI image**. The platform never knows or cares which language produced it.
Language support becomes *data* (a runtime definition file), not *code*. Adding a new language is one
YAML file and two container images; it touches no scheduler, no control plane, no core.

Those images run inside **Firecracker microVMs**, because the entire product is "run strangers' code"
and hardware virtualization is worth its cost. **Wasmtime** is a second, opt-in runtime for workloads
that need sub-millisecond cold starts and very high density — never an automatic optimization, because
most languages do not compile to WebAssembly and a platform that silently switches runtimes is one
nobody can predict.
